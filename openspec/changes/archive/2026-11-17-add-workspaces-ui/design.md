## 数据模型（本变更）

```ts
interface Session {
  id: string;            // 本地 id
  title: string;         // 首条用户消息截断，可重命名
  createdAt: string;
  updatedAt: string;
  sessionId?: string;    // 来自 agent 事件，供后续续接
  messages: ChatMsg[];   // 复用现有结构
}

interface SessionStore {
  activeId: string;
  sessions: Session[];
}
```

存储：`localStorage["myflicker.sessions.v1:" + profileId]`。

迁移：若该 key 不存在，读取旧键（`myflicker.chat.messages.v1:<profileId>`，再回落到全局键），迁移成一条标题为「历史对话」的会话。

## 行为

- 新建：插入空会话并设为 active；不打断已在执行的请求（执行中禁用新建？否，允许并行查看，但同一时间只允许一个请求）。
- 标题：首条用户消息前 24 字；重命名后不再自动覆盖。
- 删除：删除当前会话后选择下一条；全部删完时自动新建空会话。
- 清空：只清当前会话的消息，会话本身保留。
- 切换会话：中止当前流（可选，实现为保留后台流并在完成后写回原会话；本期简化为允许切走，流继续写回原会话）。
- 离线：会话列表可浏览，输入禁用；不影响切换历史会话。

## 后续阶段（不在本变更）

1. 项目切换：需要网关支持按请求指定 cwd（新接口或参数），并做沙箱校验。
2. 右面板：先做变更 diff，再做 `WebContentsView` 浏览器。
3. 连接设置抽屉：把现有「连接」页折叠成右侧抽屉，整页保留为兜底。
4. agent 续接：网关接受 `session_id` 并透传 `--resume`，工作区提供「继续」按钮。
